# M3 AI 入局（LLM 座位）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 房间内可配置 AI 座位（LLM 驱动，Claude API），与真人混合对局；决策链路"枚举 → 启发式预筛 → LLM 选择 → 引擎校验 → 降级"，对局永不卡死。

**Architecture:** 新增 `packages/llm`：`HeuristicAgent`（纯函数评估器，预筛+降级+M4 复盘锚点三用）、`summarize`（局势 → 紧凑文本 prompt）、`LLMAgent`（Claude API，structured output）。server 侧：RoomManager 支持 AI 座位填充、GameSession 外挂 AI 驱动循环。规则仍只在 engine 结算——**LLM 只做选择**。

**Tech Stack:** TypeScript strict、@anthropic-ai/sdk、Vitest（fixture 不烧 token）。

**上游契约：** engine `PlayerAgent { chooseAction(state, legal): Action }` 已存在（agents/random.ts）；server `GameSession.submitAction/seat 校验/currentSeat/finished`、`RoomManager`（满员才开始——本计划放宽）、protocol `SeatInfo.isAI` 已有字段；web 座位列表已渲染 connected。

## Global Constraints

- 规则只在 engine 结算；LLM 输出必须经 `enumerateActions` 匹配校验，非法 → 带原因重试一次 → 降级 HeuristicAgent Top-1（记日志）
- **CI 与全部测试不烧 token**：API 调用走可注入 `ClaudeClient` 接口，测试用 fixture
- API key 走 `ANTHROPIC_API_KEY` 环境变量；提供 `.env.example`（gitignored 已有 .env.*）；key 缺失时 AI 座位静默降级为 HeuristicAgent（日志标注），房间照样能开
- AI 决策异步执行，不阻塞 ws 消息循环；决策期间广播 `ai_thinking`（seat）
- 单次决策目标 < 10s（含 1 次重试）；prompt 前缀模板化
- 新增 package 同步 CI（聚合自动覆盖，确认即可）
- Git 工作流：禁直推 main；分支 feat/m3-*；commit 带 `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` 尾注
- 每个 commit 前根目录 `npm run typecheck && npm test` 全绿

### Task 1: llm 包脚手架 + 启发式评估器（HeuristicAgent）

**Files:**
- Create: `packages/llm/package.json`、`tsconfig.json`、`vitest.config.ts`
- Create: `packages/llm/src/heuristic.ts`
- Test: `packages/llm/test/heuristic.test.ts`

**Interfaces:**
- Consumes: engine 全部（GameState/Action/enumerateActions/data 常量/network helpers）
- Produces:
  - `scoreAction(state: GameState, player: PlayerIndex, action: Action): number`——纯函数快速评估。分量（权重先写死为常量对象导出，便于调参）：
    - build：板块 (vp×2 + incomeAdvance×3 + linkIcons×1) / 总成本（£+煤铁市价折算，用 engine `buyCoalCost/buyIronCost`）；煤矿连通商人位的市场售卖预期（engine `connectedMerchants` + `marketSellRevenue`）；铁路时代高级板块加成（防止比值评分系统性偏好便宜 L1——加一条"L4 棉纺在铁路时代分数 > L1 棉纺"方向性测试）
    - network：新连通地点数 ×2；连通商人位 +3；铁路时代建边基础分
    - sell：翻面板块的 vp×2 + incomeAdvance×3；商人啤酒奖励（vp 直接加、income +2×3、£5/2、develop +4）
    - develop：解锁高级的潜在收益（下一级 vp+income 差）− 铁成本
    - loan：现金短缺时 +5，否则 −3（退收入的长期代价）
    - scout：−1（节奏代价）；pass：0
  - `class HeuristicAgent implements PlayerAgent, DecidingAgent { chooseAction(state, legal): Action; decide(state, player, legal): Promise<Decision> }`——chooseAction 选 scoreAction 最高者（并列取数组序）；decide 是 async 包装（reason 固定文案、degraded: true、usage: 0）——降级模式下与 LLMAgent 同接口
  - `prescreen(state, player, legal, k): Action[]`——按 scoreAction 降序取 Top k（LLM 候选集）
  - 统一决策接口（Task 3/4 共用，server 只依赖它）：
    ```ts
    interface Decision { action: Action; reason: string; degraded: boolean; usage: { input: number; output: number } }
    interface DecidingAgent { decide(state: GameState, player: PlayerIndex, legal: Action[]): Promise<Decision> }
    ```

### Task 3: ClaudeClient + LLMAgent（决策链）

**Files:**
- Create: `packages/llm/src/client.ts`、`packages/llm/src/llm-agent.ts`
- Create: `packages/llm/test/fixtures.ts`（录制响应）
- Test: `packages/llm/test/llm-agent.test.ts`

**Interfaces:**
- Produces:
  - `interface ClaudeClient { decide(req: { system: string; user: string; candidates: number; model: string; maxTokens: number; timeoutMs: number }): Promise<{ choiceIndex: number; reason: string; usage: { input: number; output: number } }> }`——tool use 强制结构（`choose` tool：choice_index + reason）
  - `class AnthropicClient implements ClaudeClient`（@anthropic-ai/sdk；model 默认环境变量 `BRASS_AI_MODEL` 或 `claude-sonnet-4-5`；timeout 用 SDK timeout 选项）
  - `class LLMAgent implements DecidingAgent`（Task 1 的统一接口）——座位在 `decide(state, player, legal)` 的参数上，不绑构造
  - 决策流（`decide`）：
    1. `prescreen(state, player, legal, topK)`（难度：easy 8 / normal 20 / hard 40）
    2. `buildDecisionPrompt` → `client.decide`
    3. choiceIndex 越界或匹配不上 → 带错误原因重试一次（prompt 追加"上次回复无效：…"）
    4. 再失败或 API 异常（超时/网络/余额）→ 降级 HeuristicAgent Top-1，`degraded: true`
  - `DIFFICULTY: Record<'easy'|'normal'|'hard', { topK: number; model: string; maxTokens: number; timeoutMs: number }>`——easy 用 `claude-haiku-4-5` + 8s 超时，normal/hard 用 sonnet + 8s；hard 的 user prompt 附"未来两轮前瞻"段（简要：时代进度与剩余轮数）

### Task 4: server 集成——AI 座位与驱动循环

**Files:**
- Modify: `packages/server/src/rooms.ts`（AI 座位）、`packages/server/src/ws.ts`（驱动循环）、`packages/server/src/main.ts`（env）
- Modify: `packages/protocol/src/index.ts`（AI 配置 + ai_thinking 消息）
- Create: `.env.example`
- Test: `packages/server/test/ai-seats.test.ts`

**Interfaces:**
- Consumes: llm 包（LLMAgent/HeuristicAgent/AsyncPlayerAgent）、protocol
- Produces:
  - protocol 变更：`RoomConfig` 加 `aiSeats?: { count: number; difficulty: 'easy'|'normal'|'hard' }`（**createRoom 校验 1 <= count <= playerCount - 1**，非法回 'invalid-config'）；`SeatInfo.isAI` 已有；下行消息加 `{ type: 'ai_thinking'; protocolVersion: number; seat: PlayerIndex; thinking: boolean }`；`action_applied` 加可选 `reason?: string`（AI 理由，日志展示）。全部可选新增，PROTOCOL_VERSION 保持 1
  - RoomManager：**startGame 条件 = 真人座位数 >= 1 且（满员 或 真人 + aiSeats.count >= playerCount）**；AI 填充数 = `min(aiSeats.count, playerCount - 真人数)`（clamp）；AI 座位昵称自动（"AI-1（普通）"）；**toRoomState 同步修改**：广播 config 从只含 playerCount 扩为 `{ playerCount, aiSeats? }`（仍不含 seed），seat 的 isAI 不再硬编码 false
  - AI 座位 token：伪造 crypto token 满足 GameSession 构造，但**永不进 tokenIndex、永不下发**（resume 不可达）
  - **agent 注入缝**：`createGameServer` options 加 `aiAgentFactory?: (seat: PlayerIndex, difficulty: 'easy'|'normal'|'hard') => DecidingAgent`——测试注入 fixture；main.ts 读 env 构造 AnthropicClient 后经此传入
  - AI 驱动循环（ws.ts）：startGame/submitAction/**resume** 后 `void driveAI(session)`——`while (!finished && seatIsAI(currentSeat)) { 广播 ai_thinking(true); const { action, reason, degraded } = await agent.decide(state, seat, legal); session.submitAction(seat, action); 广播 action_applied（带 reason）+ snapshots; } 广播 ai_thinking(false)`。**并发与兜底（对局永不卡死的实现路径）**：
    - 同一 session 同时只有一个 driveAI（并发守卫标志）
    - **循环体整体 try/catch**：任何未预期异常（summarize/prescreen bug、submitAction 非预期抛出、API 层漏网异常）→ error 日志 + 末级 fallback HeuristicAgent Top-1 直接 submitAction（再失败才放弃并 ai_thinking(false)）
    - resume/心跳路径重触发 driveAI（幂等，守卫防重入）
  - main.ts：读 `ANTHROPIC_API_KEY`；缺失 → aiAgentFactory 返回 HeuristicAgent（启动日志警告）
  - usage 统计：每 AI 决策记录（M4 用，本任务先记到 game 的内存 + 终局日志行）；真 API 冒烟时核对单次决策成本（目标 < $0.01/decision）
  - **prompt 卫生不变式**：nickname/聊天/日志文本永不进 prompt（summarize 只读 GameState）——写进 summarize.ts 头注释

- [ ] **Step 1: 失败测试**（fixture ClaudeClient 经 `aiAgentFactory` 注入 server：2 真人 + 2 AI 开局完整对局；AI 决策链走通；ai_thinking 广播；**aiSeats.count 边界**（count=0/count=playerCount → 'invalid-config'；3 真人+count=2 的 4p 房 clamp 补 1 AI 可开局）；**driveAI 异常兜底**（agent.decide 抛非 API 异常 → Heuristic Top-1 兜底对局不卡死）；key 缺失降级）
