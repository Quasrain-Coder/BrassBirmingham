# 架构反思：LLM 自由选择是负资产——argmax 对照实验与制胜方程（2026-09-06）

> 触发：用户指出「迭代效率低，本质是没彻底理解游戏」。本文是回应：从 90 局
> 数据与引擎计分代码出发，测量「LLM 在决策回路里的真实增量」，结论推翻了
> 前四轮迭代的隐含架构假设。

## 实验一：冠军 vs 非冠军的表层行为几乎无差

90 局（a/b/c 三轮）全部席位按是否冠军分组（87 冠军席局）：

| 指标（每局均值） | 冠军 | 非冠军 |
|---|---|---|
| 铺路 | 9.6 | 9.7 |
| 贷款 | 3.3 | 3.3 |
| 研发 | 2.3 | 2.8 |
| 搜寻 | 0.9 | 0.9 |
| 卖单 | 3.2 单 × 均 7.3VP | 2.8 单 × 均 6.8VP |
| 冠军建厂 Top | 酒厂L2(157) 煤L2(86) 棉L1(76) 酒厂L3(76) 铁L2(72) | — |

宏观行为结构无法区分冠军与凡人。胜负手在**微观**：哪座城、哪一级、何时翻
——即每一步的期望值评估精度。

## 引擎制胜方程（era.ts 吃透）

- VP = 翻面板块 VP × 时代计分次数（运河 L2+ 翻面**双倍**）+ Link 分。
- Link 分 = 每条边 Σ(两端城市已翻板块 linkIcons) + 商人位 2——Link 价值是
  「两端翻面密度」的函数，铺路前要推演未来翻面，逐局模拟才能算准。
- 钱/收入终局不折 VP（仅 tiebreaker）——「收入≈终局VP」是错误模型。
- 4 席 31 决策/局：每步期望差 0.5VP，30 步就是 15VP 分差——**微观评估精度
  就是全部棋力**。

## 实验二：argmax 对照——LLM 自由选择一致劣于「信评分排序」

argmax = LLM 席位零调用、直接选 prescreen（快评分器）Top-1。同种子同席位
对照（a/b/c/d 四轮全部）：

| 组 | LLM 自由选择 | argmax 对照 | LLM 增量 |
|---|---|---|---|
| c0（v6 variant） | 75.0 | 89.3 | **−14.3** |
| c1 | 79.4 | 88.1 | **−8.7** |
| c2 | 87.7 | 95.5 | **−7.8** |
| d0（具体 prompt） | 71.4* | 85.9 | −14.5 |
| d1 | 70.4* | 94.1 | −23.7 |
| d2 | 78.3* | 94.0 | −15.7 |

*d 组为 7/10 局中途值。

**结论：LLM 的自由选择在所有配置下都是负贡献（−8 ~ −24 VP）。** 前四轮
prompt 工程的隐含假设——「LLM 理解游戏后能选得比评分器好」——被证伪。
我们在训练 LLM 重建一个启发式已经拥有的评估器（flipProb 模型、商人稀缺、
市场饥渴、2-ply 前瞻），它永远追不上，因为游戏理解在评分函数里而不在
语言先验里。

## 架构结论与重定位

1. **短期（确定性收益）**：
   - LLM 座位的兜底顺序改为「prescreen argmax 优先，LLM 仅在候选分差 < ε
     时仲裁」（现 HeuristicAgent 降级是 2-ply 全量评分，比 argmax 强但慢）；
   - SHOW_SCORES（候选描述附快评分）实验验证数值对齐能否把 −8~−24 收窄
     到接近 0——若成功，LLM 定位为「评分解释器 + 长尾仲裁」。
2. **中期（真正理解游戏的迭代对象是评分器，不是 prompt）**：
   - 翻面概率模型（flipProbability）与商人啤酒稀缺是微观评估的核心，v905
     消融已证明该路线可控可测；
   - rollout 复核（rolloutK）是「用模拟代替静态估值」的已实现未放量项，
     成本 2.5min/局，适合 server 场景（AI 步进 5s）。
3. **LLM 的差异化价值（若保留）**：长期规划/流派承诺（computePlan 单维）、
   对手建模（启发式基本没有）——这些是评分器结构性缺失的部分，但属研究级
   难题，不应再作为 prompt 工程的目标。

## 方法论教训（前四轮的复盘）

- 「症状→prompt 补丁」的迭代上限 = argmax 基线与 LLM 的差距，且每轮 ~2h
  只能买回几分；先测「零智力基线」（argmax）再决定迭代对象，一小时的
  控制实验省掉一轮无效迭代。
- 同理适用于任何「LLM + 工具评分器」混合系统：先量出评分器单独的水平，
  再评估 LLM 增量，避免在负增量组件上做局部优化。
