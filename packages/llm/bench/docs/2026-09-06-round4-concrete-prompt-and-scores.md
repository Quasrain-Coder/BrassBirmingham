## 三个否定性结论

1. **prompt 具体化（d 组）反而更差**（80.7 → 72.0）：【每步检查单】把模型
   变成僵化的规则执行者——规则是静态的，局面是动态的，逐条对照检查单的
   模型丢掉了情境裁量（例：煤矿配额导致它在铁厂更差时也绕开煤矿）。
2. **数值对齐（e0 组）无效**（74.7 ≈ 75.0）：给模型看启发式分数没有改变
   选择质量——它既不稳定地对齐 rank0（那就退化成 argmax），也不稳定地
   找到 rank0 的错误（那是它没有的能力）。9/10 垫底与 c 组持平。
3. **LLM 自由选择的负增量在全部 5 个变体（a/b/c/d/e）成立**（−8 ~ −24），
   且 prompt 工程无法收窄。负增量的来源不是"选错方向"而是**微观评估精度
   不足**：每局 31 决策，每步差 0.5VP 期望就是 15VP——这正是启发式
   flipProb/稀缺/市场模型与 2-ply 前瞻所承载的能力，语言模型没有等价物。

## 生产建议（按证据强度排序）

1. **LLM 座位默认走 argmax 兜底**（或直接用 HeuristicAgent 2-ply）：在
   当前模型与评分器水平下，LLM 主选择每局净亏 8-24 VP。LLMAgent 已有
   降级路径，改为「默认降级、LLM 仅白名单场景启用」即可落地。
2. **LLM 重新定位到评分器不覆盖的环节**（需要专门验证，不应默认开启）：
   终局派系承诺、对手意图建模、赛后复盘解说（summarize 链路已具备）。
3. **棋力提升的正确对象是评分器**：flipProb 模型校准、商人啤酒稀缺、
   rollout 复核放量（v905 消融已验证该路线可控可测）。

## 方法论沉淀

- 「零智力基线」先行：任何混合智能系统（LLM + 工具评分器）先测工具单独
  的水平，再测 LLM 增量——一小时的控制实验省掉整轮无效迭代。
- prompt 的表达力不是自由度：具体规则在静态基准上好看，在动态博弈里
  因无法枚举全部情境而劣于「评估器 + 简单原则」。
- 逐局即时报告（用户要求的流程改进）在此后所有跑批中执行：每局 GAME DONE
  后立即输出「本局 VP/名次/关键决策/与对照差异」。
